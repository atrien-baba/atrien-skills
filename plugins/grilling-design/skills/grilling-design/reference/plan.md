# Plan (flat plan)

The flat plan is the single most skipped stage in AI-made pieces, and the reason they come out crowded: pages get composed before anyone decided what each one says.

## Round 1: how the pages divide

Offer two or three divisions as **page skeletons rendered to one image** (HTML boxes, grayscale, labelled; ~1 minute of work). Each option differs in what the reader meets first, e.g. *what it does → how to start*, *problem → solution*, *one page per variant*. State for each what it wins and what it costs.

## Round 2: one sentence and one hero per page

For each page ask:

- the message in **one sentence** (if it needs two, split the page or cut),
- the **hero**: the one element the eye lands on first,
- the supporting items and the assets they use,
- what is dropped.

Keep the maker's own words in the sentence; do not polish copy here.

## Artifact: `design/plan.md`

```markdown
# 台割：<piece>（v1, YYYY-MM-DD）

| ページ | 伝えること（1文） | 主役 | 脇役 | 素材 | 落とすもの |
|---|---|---|---|---|---|
| P.06 | | | | | |
| P.07 | | | | | |
```

Keep every version (v1, v2…) so a later Proof round can point back to the row it came from. Done when every row has one sentence and one hero, and the maker has confirmed the table.
