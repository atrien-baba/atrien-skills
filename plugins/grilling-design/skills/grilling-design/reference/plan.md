# Plan（台割）

The flat plan is the most skipped stage in AI-made pieces, and the reason they come out crowded: pages get composed before anyone decided what each one says.

## Round 1 (Piece only): how the pages divide

Offer two or three divisions as **page skeletons rendered to one image** (HTML boxes, grayscale, labelled; about a minute of work). Each option differs in what the reader meets first, e.g. *what it does → how to start*, *problem → solution*, *one page per variant*. State for each what it wins and what it costs. A Page-size job skips this round.

For a redesign, start from the current pages' contact sheet with keep/change marks instead of blank skeletons, and draft the whole table from the current piece; the maker confirms or edits rows rather than filling eighty cells.

## Round 2: one sentence, one hero, one owner per page

For each page ask:

- the message in **one sentence** (two sentences → split or cut),
- the **hero**: the one element the eye lands on first,
- the supporting items, the assets they use and each asset's state,
- the copy owner and the date the text is final,
- what is dropped.

Keep the maker's own words in the sentence; copy is written and checked after the table is confirmed, not polished here.

## Artifact: `design/plan.md`

```markdown
# 台割：<piece>（v1, YYYY-MM-DD）承認：○○（YYYY-MM-DD）

| ページ | 伝えること（1文） | 主役 | 脇役 | 字数の目安 | 素材と状態 | 原稿：担当・確定日 | 落とすもの |
|---|---|---|---|---|---|---|---|
| P.06 | | | | | 写真：有 ／ 図：作図待ち（○○ 10/15） | | |

素材の状態：有 ／ 撮影待ち ／ レンダー待ち ／ 作図待ち ／ 権利確認 ／ 仮画像（FPO）
```

Keep every version (v1, v2…) so a Proof round can point back to the row it came from.

Done when every row has one sentence, one hero, a copy owner and an asset state, and the approver has confirmed the table (name and date in the heading). Proof does not open on a page whose copy is not final; pages carrying 仮画像 keep a list of them until replaced.
